# Labs 9.1–9.2 — hybrid envelope encryption and re-keying; ML-DSA tokens against the header budget

**Lab 9.1** implements X-Wing, the CFRG hybrid KEM (X25519 + ML-KEM-768) that HPKE's
post-quantum draft registers and Cloud KMS ships, checks it against the draft's test vector,
then uses it for envelope encryption: each object under its own AES-256-GCM data key, the
data key wrapped under a long-lived KEK. `envelope.py` builds a 200-object store under an
RSA-OAEP KEK, re-keys it to ML-KEM-768 and then X-Wing by rewriting only the wrapped keys,
and crypto-shreds the KEK. **Lab 9.2** issues and verifies ML-DSA-signed JWTs per RFC 9964
(`alg` ML-DSA-44/65/87, JWK `kty` AKP) and measures them against cookie and header limits.

| File | What it is |
|---|---|
| `solution/xwing.py` | X-Wing KEM (reference). `starter_xwing.py` is your file. |
| `solution/envelope.py` | DEK wrapping (RSA-OAEP / ML-KEM-768 / X-Wing), sidecar headers, `rekey()`, `shred()`. |
| `solution/jws_mldsa.py` | Compact JWS with ES256/EdDSA/ML-DSA, AKP JWKs, budget table. `starter_jws_mldsa.py` is your file. |
| `fixtures/xwing_tv1.json` | First test vector from draft-connolly-cfrg-xwing-kem-10. |
| `data/objects/` | Generated by `envelope.py`; disposable. |
| `results/` | Reference outputs (`envelope.json`, `jws.json`, and the printed `.txt`). |

```bash
pytest labs/ch09/tests                          # PQ_LAB_IMPL=solution pytest ... runs the reference
python labs/ch09/solution/xwing.py
python labs/ch09/solution/envelope.py           # 200 x 64 KiB objects; ~1 s
python labs/ch09/solution/jws_mldsa.py          # uses labs/ch07/ca/mldsa65 for the x5c row if present
```

Header budgets in `jws_mldsa.py` are common defaults (RFC 6265 cookie minimum, nginx and
Apache header-line defaults, 16 KB totals on managed load balancers and Node.js); check
your own stack's values. `xwing.py` is a teaching implementation; use a maintained library
or your KMS for production.
